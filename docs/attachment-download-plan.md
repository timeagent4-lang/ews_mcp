# 附件下载实施计划

目标：复用 exports/<邮箱>/ 文件保存能力，增加 prepare_attachment_download 和
短期签名 GET 下载接口。AI 执行器接收原始字节，模型只接收文件信息和链接。
本窗口实施附件功能；搜索和会议发送/文案保持原状。

用户已授权在当前共享工作区实施。其他窗口只读；不创建分支、不提交、不推送。
当前仓库无首次提交，修改前六个文件已备份至系统临时目录
ews-mcp-attachment-baseline-20260922，用于逐项审查。

## 设计约定

- 新工具沿用 params.lanid/name、现有 OA 和 DELEGATE 连接、_tool_item 范围校验。
- 每次准备下载重新验证邮件/附件归属；第一版不对不同请求复用旧附件。
- _save_export 改为分块落盘，并保留原 saved_path 返回合同；新工具不返回路径。
- SQLite 记录缓存文件、原文件名、大小、SHA-256、保留期限及写入中状态。
- 单实例部署为目标；同目录并发使用 SQLite 原子预留限制文件数和总容量。
- 写入先 .part，成功原子重命名；失败删除临时文件并释放预留。
- 链接为 bearer 凭证，仅限制到单个随机下载 ID 和有效期，不宣称绑定下载者身份。
- GET 只接受下载 ID、expires、token；禁止接受文件路径或邮箱参数。
- 定期清理只管理新增索引中的文件，保留现有未索引导出文件。
- 默认关闭下载功能；默认原文件上限 5 MiB、总缓存 1 GiB、1000 个文件、
  链接 600 秒、文件保留 24 小时、清理间隔 300 秒。配置错误明确拒绝。
- 继续复用 7712:7805 映射；PUBLIC_BASE_URL 明确使用执行器可达地址。
- 不增加第三方运行依赖。真实 OA/Exchange 与审计模块需内网联调。

## 重点验收

1. 服务端路径、邮箱及凭据不进入下载 URL/结果。
2. 文件正文不进入 MCP 结果；只将链接元数据同步到 content 和 structuredContent。
3. 超限数据最多读取上限加一个字节；异常不留下有效记录或占用配额。
4. 缺失、伪造、过期凭证分别被拒绝；有效期内可重试，服务重启后仍可下载。
5. 空文件、中文文件名、恶意路径形式文件名、并发配额、已删除缓存明确处理。
